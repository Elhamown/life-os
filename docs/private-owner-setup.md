# إعداد كلمة مرور المالك محليًا دون مشاركة الأسرار

الأداة المحلية: `scripts/setup-owner-secrets.mjs`. لا تستورد التطبيق أو SDK، ولا تقرأ بيانات بيئتك أو تتصل بالشبكة أو بقاعدة بيانات. لا ترسل كلمة المرور إلى Codex أو ChatGPT أو GitHub أو أي موقع توليد تجزئات. لا تحفظ كلمة المرور نفسها في ملف.

## صيغة التحقق الفعلية

المصدر: `passwordMatches` في `app/lib/private/crypto.ts` و`getConfig` في `app/lib/private/config.ts`.

```text
scrypt$32768$8$1$<salt:64 hex characters>$<derived key:128 hex characters>
```

- خوارزمية scrypt: `N=32768`, `r=8`, `p=1`، مفتاح مشتق بطول 64 بايت، `maxmem=67108864` بايت.
- salt عشوائي من 32 بايت، بترميز hexadecimal (64 حرفًا).
- المفتاح المشتق بترميز hexadecimal (128 حرفًا)، وليس base64 أو bcrypt أو Argon2.
- كلمة المرور تُشفّر إلى UTF-8 قبل الاشتقاق. لا قصّ للمسافات أو تغيير للعربية أو تطبيع Unicode؛ أدخلها لاحقًا بالطريقة نفسها.
- التحقق يستخدم `timingSafeEqual`. يقبل المدقق نمط hex بالأحرف الكبيرة أو الصغيرة؛ الأداة تكتب lowercase.
- الأداة تطلب 16–128 وحدة UTF-16 (طول JavaScript، متوافق مع حد حقل الدخول)، وبحد أقصى 512 بايت UTF-8، مع تأكيد كلمة المرور. بعض الرموز مثل emoji تُحسب وحدتين.

## تشغيل الأداة على جهازك فقط

1. استخدم جهازك الموثوق وطرفية محلية خاصة غير مسجلة، دون مشاركة شاشة أو session recording. لا تشغّلها داخل Codex أو GitHub Actions أو طرفية سحابية أو خدمة عامة.
2. أداة الإعداد متوافقة مع Node.js 22.23.1 و24. المشروع وتكوين Vercel ما زالا يستخدمان Node.js 24؛ لا يلزم تغييرهما لتشغيل الأداة محليًا. لا تحتاج الأداة `npm install` أو شبكة. على macOS/Linux استخدم طرفيتك المحلية. على Windows استخدم WSL محليًا ومسار home الخاص بلينكس؛ الأداة ترفض Windows الأصلي لأن Unix modes لا تضمن Windows ACL.
3. من نسخة المستودع التي تحتوي الأداة شغّل:

   ```sh
   node scripts/setup-owner-secrets.mjs
   ```

4. اختر كلمة مرورك وأدخلها ثم أكّدها. الإدخال مخفي دون نجوم. لا تضعها في وسيطة أمر، أو متغير shell، أو ملف داخل المستودع، أو محادثة. Ctrl+C يلغي العملية.
5. لا تظهر كلمة المرور أو التجزئة أو المفاتيح. يظهر **مسار مجلد فقط** داخل home، باسم `.madar-owner-secrets-…`. يُنشأ مجلد جديد في كل تشغيل، بصلاحيات `700`، وثلاثة ملفات `600` دون استبدال ملفات موجودة:

   على macOS يكون المسار عادةً `/Users/<اسمك>/.madar-owner-secrets-<لاحقة عشوائية>/`. تتحقق الأداة من المسارات الفعلية بعد حل الروابط الرمزية، وترفض التشغيل إذا كان home داخل مستودع الأداة، قبل طلب كلمة المرور أو توليد القيم.

   | اسم الملف / متغير Vercel | المحتوى |
   |---|---|
   | `MADAR_OWNER_PASSWORD_HASH` | تجزئة scrypt الكاملة؛ ليست كلمة المرور الصريحة |
   | `MADAR_SESSION_SECRET` | 32 بايت عشوائية مستقلة من `crypto.randomBytes`، ممثلة بـ64 حرف hex |
   | `MADAR_STORE_ENCRYPTION_KEY` | 32 بايت عشوائية مستقلة أخرى من `crypto.randomBytes`، ممثلة بـ64 حرف hex |

الـsalt يستخدم استدعاء عشوائي مستقل أيضًا. لا إعادة استعمال للمفتاح بين الوظائف. لا تستخدم قيم الاختبارات أو كلمات الأمثلة كأسرارك.

**ترميز سر الجلسة:** الكود يقبل نصًا بطول 64 حرفًا على الأقل؛ اختيار hex هنا توصية من الأداة وليس شرطًا عامًا في المدقق. تستخدم JWT نص الـhex نفسه كـUTF-8، ولا تفك ترميزه قبل إدخاله في Vercel.

**ترميز مفتاح التخزين:** hex من 64 حرفًا بالضبط شرط إلزامي؛ يفك الخادم ترميزه إلى 32 بايت لتشفير AES-256-GCM. لا تضع base64 أو كلمة مرور أو تجزئة أخرى مكانه.

الأداة القديمة `npm run notion:password` تخفي الإدخال لكنها تطبع التجزئة. استخدم الأداة الجديدة إذا أردت عدم إظهار القيم في الطرفية. لم يتغير منطق المصادقة أو الأمر القديم.

### تنزيل الأداة على macOS

من Terminal محلية، في مجلد عادي مثل `~/Projects` خارج iCloud Drive، احصل على الفرع:

```sh
git clone --branch feature/fix-owner-terminal-input --single-branch https://github.com/Elhamown/life-os.git
cd life-os
node --version
node scripts/setup-owner-secrets.mjs
```

تأكد أن إصدار Node هو `v22.23.1` أو يبدأ بـ `v24.`. أمر Git ينقل الكود فقط؛ نفّذه قبل إدخال أي كلمة مرور. لا حاجة لتشغيل الموقع أو `npm install` أو نشره. إذا لديك نسخة بالفعل اتبع أوامر تحديث الإصلاح أدناه مع الحفاظ على أي تعديلات محلية.

## نقل القيم دون عرضها

انسخ كل ملف مباشرة للحافظة، ثم ألصقه في حقل البيئة الخاص؛ لا تستخدم `cat` أو `echo`. في الأوامر التالية استبدل `/absolute/private/directory` بالمسار الذي ظهر، وليس بقيمة سرية.

macOS:

```sh
pbcopy < "/absolute/private/directory/MADAR_OWNER_PASSWORD_HASH"
```

Linux مع Wayland (إذا كانت أداة wl-copy مثبتة):

```sh
wl-copy < "/absolute/private/directory/MADAR_OWNER_PASSWORD_HASH"
```

غيّر اسم الملف إلى `MADAR_SESSION_SECRET` ثم `MADAR_STORE_ENCRYPTION_KEY` لكل عملية نسخ. لا تستخدم مدير حافظة يزامن القيم سحابيًا؛ امسح الحافظة بعد الانتهاء. يمكنك نقلها إلى مدير أسرار محلي موثوق دون عرض القيم. لا تضع الملفات في Git أو مجلد تتم مزامنته إلى خدمة عامة.

## إضافتها إلى Vercel

توليد القيم محلي بالكامل. نشر التطبيق يحتاج إرسال **التجزئة والمفاتيح** إلى مخزن بيئة Vercel الخاص؛ كلمة المرور المختارة نفسها لا تُرسل أثناء التوليد. عند تسجيل الدخول لاحقًا تُرسل كلمة المرور عبر HTTPS إلى تطبيقك المنشور على Vercel للتحقق منها. هذا مختلف عن استخدام موقع طرف ثالث لتوليد تجزئة.

1. مشروع MADAR → Settings → Environment Variables.
2. أضف المتغيرات الثلاثة بأسمائها الدقيقة، والقيم فقط، دون اقتباسات أو `NAME=` أو مسافات إضافية. لا تستخدم `NEXT_PUBLIC_`.
3. اختر Preview والفرع الصحيح. استخدم مجموعة مستقلة للإنتاج. لا تغيّر مفتاح تشفير بيئة قائمة لمجرد إعادة تشغيل الأداة؛ احتفظ بمفتاح القاعدة القديمة ونسخة احتياطية آمنة منه.
4. يلزم أيضًا `MADAR_APP_ORIGIN`: أصل HTTPS الثابت الذي ستفتح منه الموقع، دون مسار أو شرطة مائلة أخيرة؛ و`DATABASE_URL`: اتصال PostgreSQL خاص مع إعداد TLS الموصى به من المزوّد وجداول MADAR المهيأة. الأداة لا تولّد اتصال قاعدة ولا تغيّرها.
5. احفظ المتغيرات، ثم أعد نشر Preview الصحيح بنفسك بعد اعتماد الإعداد. النشر القديم لا يلتقط المتغيرات الجديدة تلقائيًا. هذه الأداة لا تنشر أي شيء.

احفظ الأسرار في مكان خاص موثوق قبل إزالة الملفات المؤقتة محليًا. فقدان مفتاح التخزين قد يمنع استرداد البيانات المشفرة؛ تغييره يحتاج خطة إعادة تشفير منفصلة. تغيير تجزئة المالك أو سر توقيع الجلسة يبطل الجلسات السابقة.

## اختبار دون كشف أسرار

نافذة خاصة → العنوان المطابق للأصل → `/login` → كلمة مرورك الأصلية → الوصول إلى لوحة التحكم → تسجيل الخروج → التأكد من طلب الدخول مجددًا. لا تشارك HAR أو bodies الطلبات أو قيم Cookies؛ قد تتضمن كلمة المرور أو الجلسة. لا تحتاج أي تكامل Notion لهذا الاختبار.

اختبارات الأداة تستخدم كلمة مرور اصطناعية وعشوائية **ثابتة محقونة للاختبار فقط**؛ تتحقق من مطابقة مدقق المصادقة الحقيقي والترميزات ورفض الإدخال غير التفاعلي، دون إنشاء أسرار حقيقية أو تشغيل تكاملات.

## إصلاح قارئ الطرفية والأخطاء الآمنة

وجدنا عيوبًا قابلة لإعادة الإنتاج في القارئ السابق، دون كلمة مرور حقيقية:

- كل طلب إدخال كان يُغلق raw mode ويفصل listener ثم يعود في الطلب التالي. هذا أتاح نافذة echo، وأضاع بقية دفعة الإدخال بعد أول Enter.
- إذا وصلت `CR` ثم `LF` منفصلة، فسّرت `LF` المتأخرة على أنها تأكيد فارغ؛ قد يظهر اختلاف مصطنع حتى لو أدخل المستخدم كلمة المرور نفسها.
- علامات bracketed paste التي تدعمها macOS Terminal (`ESC[200~` و`ESC[201~`) كانت مرفوضة كمحارف تحكم.
- الرسالة العامة أخفت الفرق بين هذه الحالات، وكلمة مرور قصيرة، واختلاف فعلي، وفشل إنشاء الملفات. لا يمكن معرفة أيها حدث على جهازك من الرسالة القديمة وحدها.

الإصلاح يستخدم جلسة raw واحدة للطلبين، يحتفظ ببقية الدفعات، يعالج CRLF عبر حدود الدفعات، ويقبل delimiters اللصق دون إدخالها في كلمة المرور. لا تُقصّ المسافات ولا تُطبّع كلمة المرور. اللصق متعدد الأسطر يُرفض برسالة واضحة؛ انسخ سطر كلمة المرور وحده ثم اضغط Enter. Backspace وDelete يحذفان محرف Unicode كاملًا، وCtrl+C يلغي. تُعاد حالة الطرفية عند النجاح أو الفشل، دون طباعة الإدخال.

الأخطاء تعرض رمزًا عامًا فقط، دون password/hash/keys أو الاستثناء الأصلي:

| الرمز | الإجراء الآمن |
|---|---|
| `TERMINAL_REQUIRED` | Terminal محلية، دون pipes أو إعادة توجيه أو وسائط |
| `PASSWORD_POLICY` / `PASSWORD_TOO_LONG` | 16–128 وحدة UTF-16 وبحد أقصى 512 بايت UTF-8 |
| `PASSWORD_MISMATCH` | التأكيد مختلف فعلًا؛ أعد إدخاله محليًا |
| `INPUT_MULTILINE` | انسخ كلمة المرور وحدها دون newline؛ ثم Enter |
| `INPUT_CONTROL` | استخدم الكتابة أو اللصق العادي وBackspace؛ لا مفاتيح الأسهم |
| `INPUT_CANCELLED` / `INPUT_EOF` | أُلغي الإدخال أو انتهى؛ أعد الأمر عند الاستعداد |
| `OUTPUT_LOCATION` | تحقق من home ومسار نسخة الأداة |
| `OUTPUT_IN_REPOSITORY` | ضع المستودع في `~/Projects/life-os`، لا تجعل home نفسه المستودع |
| `OUTPUT_WRITE` | تحقق من صلاحية الكتابة في home والمساحة الحرة؛ لا تستخدم sudo |
| `TERMINAL_IO` / `CRYPTO_FAILED` / `SETUP_FAILED` | أبلغ عن الرمز وإصدار Node فقط؛ لا تشارك قيمًا أو ملفات أسرار |

إذا تعذّر إنشاء الملفات، تُزال فقط الملفات الجزئية داخل المجلد الجديد لهذه المحاولة، ولا تُحذف ملفات سابقة. تبقى التغطية والمسار والتشفير وصيغة scrypt كما كانت؛ لم يتغير كود المصادقة.

### تحديث نسخة Mac الحالية وإعادة التشغيل

من داخل مستودعك المحلي، نفّذ `git status --short` أولًا. إذا ظهرت تعديلات محلية، احتفظ بها قبل تبديل الفرع؛ لا تستخدم reset أو force.

الأوامر التالية لأول انتقال إلى فرع الإصلاح. تعمل أيضًا إذا نُسخ المستودع سابقًا بـ `--single-branch`:

```sh
git status --short
git fetch origin feature/fix-owner-terminal-input
git switch -c feature/fix-owner-terminal-input FETCH_HEAD
node --version
node scripts/setup-owner-secrets.mjs
```

إذا كان هذا الفرع المحلي موجودًا بالفعل، استخدم `git switch feature/fix-owner-terminal-input` بدل أمر إنشاء الفرع، وتحقق أن نسختك تحتوي الإصلاح قبل التشغيل. لا يلزم `npm install` لتشغيل الأداة نفسها.

مكان الحفظ لم يتغير: `/Users/<اسمك>/.madar-owner-secrets-<لاحقة عشوائية>/`، بصلاحيات مجلد `700` وملفات `600`. لا حاجة إلى تغيير كلمة مرورك لمجرد تحديث الأداة، ولا تستبدل مفتاح تشفير قاعدة قائمة بالمفتاح الجديد دون خطة إعادة تشفير.

### التحقق الآلي

نجحت اختبارات الأداة على Node.js 22.23.1 و24.19.0. تشمل typing، plain/bracketed paste، CRLF مقسمة ومجمعة، Backspace، Unicode وUTF-8 المقسمة، confirmation، repeated prompts، إلغاء الإدخال، الرموز الآمنة، إنشاء ملفات خاصة خارج المستودع ورفض symlink إلى داخله. اثنا عشر سيناريوهًا ضمن اختبار PTY حقيقي تستخدم عشوائية ثابتة محقونة للاختبار فقط. الاختبار على Linux PTY يحاكي بايتات macOS Terminal؛ لم يتوفر جهاز macOS فعلي هنا، ولا نزعم اختبار Darwin أصليًا.

لتشغيل الفحوص فقط في بيئة تطوير مثبتة الاعتماديات:

```sh
node --conditions=react-server --import tsx --test tests/owner-setup.test.ts tests/owner-terminal.test.ts
```

اختبار PTY يستخدم Python 3 القياسية على POSIX؛ ليست مطلوبة لتشغيل أداة الإعداد. لا تُشغّل أداة الإنتاج بأسرارك داخل CI أو أي طرفية سحابية.

## تشخيص PASSWORD_POLICY دون إنشاء أسرار

أضيف وضع محلي للفحص فقط. لا يشتق تجزئة، ولا يولّد salt أو مفاتيح، ولا يكتب ملفات، ولا يتصل بالشبكة. يعرض ثلاثة حقول فقط، بعد إدخال مخفي:

```sh
node scripts/setup-owner-secrets.mjs --diagnose-input
```

```json
{"characters":32,"utf8Bytes":32,"validationPassed":true}
```

هذا مثال بأعداد اختبار اصطناعية، وليس قيمة سرية. `characters` هو طول UTF-16 نفسه المستخدم في التحقق (`String.length`)، و`utf8Bytes` طول ترميز UTF-8. لا تُعرض المحارف أو تصنيفاتها أو التجزئة أو مقاطعها. لا توجد سجلات تشخيص أو ملفات ناتجة؛ لا تعِد توجيه مخرجات الأمر إلى ملف. لا تشارك شاشة أثناء إدخال كلمة المرور.

في التشغيل العادي أيضًا تظهر هذه الحقول عند قراءة الإدخال الأول والتأكيد، قبل التحقق، دون طباعة المحارف. `validationPassed` يصف سياسة الطول فقط، وليس تطابق التأكيد. لا تزال سياسة MADAR 16–128 وحدة UTF-16 وبحد أقصى 512 بايت UTF-8. تستخدم الأداة دالة واحدة للأعداد والتحقق، حتى لا يختلف التشخيص عن شرط القبول. لا تغير scrypt أو حدود الحقل أو المصادقة.

### ما أثبتته إعادة الإنتاج وما لم نثبته

- إدخال 32 حرف ASCII يدويًا يصل إلى القارئ كاملًا في الاختبارات: 32 محرفًا و32 بايتًا، ويمر بالسياسة. لا يوجد دليل على خلل scrypt أو Node 22 في هذا المسار.
- أعدنا إنتاج تسلسل يحتوي CR/LF فارغة من مرحلة إطلاق الأمر ثم 32 حرفًا: القارئ السابق أنهى الطلب الفارغ أولًا، فمرّر طولًا صفرًا إلى `validatePassword` ورفع `PASSWORD_POLICY` رغم وجود الإدخال الصحيح لاحقًا في الدفعة. القياس الخارجي لكلمة المرور لا يقيس ما استلمه هذا الطلب.
- الإصلاح يتجاهل نهايات السطر الفارغة فقط قبل أول محرف في الطلب الأول. لا يزيل المسافات أو يحذف أي محرف كلمة مرور. إذا كتب المستخدم ثم حذف الكل، يظل الإدخال الفارغ مرفوضًا؛ والتأكيد الفارغ لا يُقبل.
- لا يمكن الجزم بأن هذه هي حالة جهازك من الملاحظات السابقة وحدها. نتيجة وضع التشخيص تحدد هل القارئ استلم العدد المتوقع. لم نستلم أي محارف حقيقية أو نتائج خاصة من جهازك.

إذا كانت الأعداد 32 و32 والنتيجة true، فهذا الإدخال يجتاز السياسة في النسخة الجديدة. إذا كانت false، فهذه أعداد النص الذي استلمه الطلب فعلًا؛ لا تولّد أسرارًا أثناء التحقيق. يمكن الإبلاغ عن الحقول الثلاثة وإصدار Node وcommit فقط؛ لا ترسل كلمة المرور أو ملفات المخرجات أو history أو تسجيل شاشة. إذا استمر الخطأ بعد true، تحقق أولًا من الفرع وcommit ومن الملف الذي تشغّله؛ لا تخفّض حدود السياسة.


هذه طريقة تعمل حتى مع نسخة `--single-branch`. إذا كان الفرع المحلي موجودًا بالفعل لا تستبدله أو تستخدم force؛ انتقل إليه وتحقق من commit. لا يلزم npm install لتشغيل الأداة. ابدأ بالتشخيص فقط؛ عند انتهاء التحقيق وإذا قررت إعداد قيمك الخاصة، الأمر العادي هو `node scripts/setup-owner-secrets.mjs` على جهازك فقط.

تم التحقق باستخدام كلمات مرور اصطناعية على Node.js 22.23.1 و24.19.0: 19 اختبارًا، منها 12 سيناريو PTY. شملت بدء الإدخال بـCRLF متبقية، الكتابة اليدوية لـ32 حرفًا، الدفعات المجمعة، والرفض الصحيح للمدخلات القصيرة والممسوحة والتأكيد الفارغ. تشغيل CLI الحقيقي في وضع التشخيص تحقّق من عدم وجود ملفات مخرجات حتى مع نجاح السياسة. الاختبارات على Linux POSIX PTY وليست جلسة macOS فعلية.
